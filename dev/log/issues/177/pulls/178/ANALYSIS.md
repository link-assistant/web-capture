# CI/CD false positives, false negatives, warnings and errors

Issue [177](https://github.com/link-assistant/web-capture/issues/177), implementation
[PR 178](https://github.com/link-assistant/web-capture/pull/178). Raw issue/PR data,
the run inventory at the start (`data/runs-initial.json`), the hive-mind
CI/CD best practices, actionlint/zizmor output before and after, and the failure
excerpts that drove the second round (`data/ci-failures-*.txt`) are in `data/`.

The first session was killed by the container OOM killer (2.9 GB cgroup limit,
`cargo` and Jest running concurrently). Its uncommitted evidence was recovered
from the `recovery/issue-177-c9678f712b22` branch; later runs build Rust with
`-j 2` and never run Rust and JS test suites at the same time.

## Templates

The hardening, `publish-retry.mjs`, `lint*.mjs`, `install-git-hooks.mjs`
and `zizmor.yml` were ported from
[js-ai-driven-development-pipeline-template](https://github.com/link-foundation/js-ai-driven-development-pipeline-template),
where they already work. None of the three templates ships a `dependabot.yml`,
but their `workflows.yml` has the same F11 gap: the zizmor action audits the
whole repository, while the path filter and the documented reproduce command
cover only `.github/workflows`, so a project that adds Dependabot gets
failures it cannot reproduce locally and does not re-check on change.

## Local verification

- `node scripts/repair-npm-lock.mjs --check` and `npm ci` with npm 12.2.0: no warnings.
- `node scripts/check-dependency-freshness.mjs npm`: only the #160 blocker remains.
- `npm run lint`, `npm run format:check`, `npm run check:duplication` pass.
- zizmor 1.30.1 (online, `.github`): no findings (`data/zizmor-after.txt`); actionlint: none (`data/actionlint-after.txt`).
- `check-js-rust-parity.mjs` against `origin/main` passes.
- `cargo test --test integration transport` (see PR description for results).
